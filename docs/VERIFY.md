# 真机验证清单

> 代码侧的自动化验证已经全部通过（`node scripts/gate.mjs`）。
> 这份清单是**需要真实账号**的那部分 —— 自动化测不到它。

---

## 前置

1. 有一个 Meoo 账号，且账号下至少有一个项目。
2. 该项目的**云服务已开通**（没有的话插件会自动尝试开通一次；仍失败就按下面第 3 步处理）。
3. 插件已装进 profile 并**重启**过 DSH：

```bash
dsh plugin --profile desktop add file:X:/Agent/deepseek插件/dsh-connect-meoo
# 然后把 "dsh-connect-meoo" 加进 profile 的 bundles，重启
```

---

## 第 1 步：端点可达（不花钱，30 秒）

```bash
node scripts/probe.mjs
```

**期望**：前 5 行都是 `ok`（401 也算 ok —— 请求打到业务层了，只是没带凭据）。

如果某一行 `--`，先解决网络（本机可能需要代理），不要继续往下走。

---

## 第 2 步：登录（API Key 最快，30 秒）

1. 打开 meoo.com → **设置 → API 密钥**，生成一串 `meoo_ak_…` 并复制。
2. 打开 DSH → 设置 → 秒悟 → 最上面的 **「API Key（推荐）」**。
3. 粘贴到输入框，点 **「保存并自动解析」**。

**期望**（几秒内）：

- 账号栏：状态「已登录」，登录方式「API Key」，项目服务 AK「已就绪」。
- 模型选择器里出现「Meoo 秒悟」一组，9–10 个模型。
- 积分栏：显示可用积分（API Key 能读积分，项目服务 AK 不能）。

> 这一步会顺带**自动开通项目云服务**（如果还没开），并换出项目服务 AK。
> 全程不弹浏览器，key 也不会过期。

### 备选：浏览器授权（不想生成 API Key 时）

1. 设置 → 秒悟 → 账号栏点 **「登录秒悟」**。
2. 浏览器弹出授权页 —— **点「授权」**。
3. 显示「授权成功」后回到 DSH。

**期望**（回到 DSH 后 10 秒内）：

- 账号栏：状态变「已登录」，登录方式「浏览器授权」，项目服务 AK「已就绪」。
- 模型选择器里出现「Meoo 秒悟」一组，约 9–10 个模型。
- 积分栏：显示可用积分数字。

**如果失败**，按现象查：

| 现象 | 原因 | 修复 |
| --- | --- | --- |
| 浏览器没弹出来 | `explorer.exe` 被拦 | 动作结果里有 `url`，手动复制到浏览器打开 |
| 授权页报 `unsupported_response_type` | 用了 `cmd /c start` 而不是 `explorer.exe` | 本插件已用 explorer，若仍出现说明是别的启动器 |
| 回调页报「state 校验失败」 | 同时开了两次登录 | 关掉旧标签页，重新点一次「登录秒悟」 |
| 粘贴 key 后报「这是项目服务 AK，不是 API Key」 | 填错类型 | 去 meoo.com → 设置 → API 密钥 复制 `meoo_ak_…` 那串 |
| 粘贴 key 后报 `API Key 无效或已撤销` | key 被删了 | 重新生成一串 |
| 授权后一直「未登录」 | 换票失败 | 账号栏会直接显示红色「登录没有完成」+ 上游原文（如 `invalid_grant`），整段贴进反馈 |
| 浏览器打开后显示「无法访问此网站 / 127.0.0.1 拒绝连接」 | 本机代理拦了回环回调 | 把**地址栏整行**复制到账号栏的「回调地址或授权码」里点「提交授权码」 |
| 授权页一直不出现 | `explorer.exe` / `rundll32` 都被拦 | 账号栏「等待浏览器授权」里有一条「手动打开授权页」链接，点它 |
| 关掉浏览器后再点「登录」没反应 | 旧会话还挂着（最长 10 分钟） | 点「重新发起登录」，会换一条新链接 |
| 「项目服务 AK 未解析」 | 项目没开通云服务 | 去 meoo.com 该项目 → 云服务 开通；或在项目对话框里发「帮我开启云服务」，然后点「刷新」 |
| 「账号下有多个项目」 | 多项目且没设默认 | 账号栏的项目下拉里选一个 |

---

## 第 3 步：对话（会花积分，一次约几分）

1. 新开一个会话。
2. 模型选择器里选 **Meoo 秒悟 → Qwen3.8-Flash**（最便宜的档）。
3. 发一句：`只回复四个字：连接成功`。

**期望**：

- 正常流式回复。
- 输入框左侧出现胶囊 `秒悟 · <数字>`。
- 回复后积分栏的数字**减少**了（不做乐观更新，点「刷新」看最新值）。

**如果失败**：

| 现象 | 原因 | 修复 |
| --- | --- | --- |
| `网关拒绝了这个 AK（HTTP 401）` | AK 属于别的项目，或项目没开通 | 换项目 / 开通云服务后点「刷新」 |
| 模型不存在（400） | 上游下架了这个 id | 点「刷新」重拉目录 |
| 流断了 / 超时 | 网络 | 见 `docs/PROTOCOL.md` 的端点表核对 |

---

## 第 4 步：工具调用（关键能力，会花积分）

发一句：

```
用 bash 工具执行 echo hello，然后把输出原样告诉我
```

**期望**：模型发起 `tool_calls`，DSH 执行工具，模型基于结果作答。

**这一步是判断「Meoo 能不能当 agent 用」的分水岭** —— 只回文本说明网关没透传
工具调用，那是这个 provider 的真实能力边界，要记进 `docs/PROTOCOL.md` 的「待验证」表。

---

## 第 5 步：界面

| 检查项 | 期望 |
| --- | --- |
| 设置 → 秒悟，五个分栏 | 账号 / 模型 / 积分 / 设置 / 诊断，切换不重新拉取 |
| 模型栏取消勾选一个模型 | 模型选择器里它**消失**（不是置灰） |
| 设置栏改刷新间隔 | 点一下即生效，不需要保存 |
| 设置栏勾「在侧边栏显示秒悟面板」 | 侧栏多一行「Meoo 秒悟」，点开是整页 |
| 取消勾选上面那项 | 侧栏那一行**消失**（注销，不是渲染空组件） |
| 诊断栏「复制诊断信息」 | 能粘贴出纯文本事实表 |
| 输入框胶囊只在选中 Meoo 模型时出现 | 换成别的 provider 的模型 → 胶囊消失 |

---

## 第 6 步：把结果记回来

任何一步失败，把**诊断栏的 `lastError` 原文**（不翻译、不概括）贴进
`docs/PROTOCOL.md` 的「待验证」表，并说明是哪一步。

**不要写「上游限制」** —— 除非你手上有那个 HTTP 状态码或业务码。
